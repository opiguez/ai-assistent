# Architectural Issues — MVP Low-Code Agent Agent

## 🔴 Критические

### 1. Инструменты — заглушки, не интегрированы с RABIS
**Файл:** `src/mcp/dataLayer/handlers.ts`  
Все `handleCreate*` возвращают захардкоженный JSON (`real_mod_uuid_111`). Рядом лежит готовый GraphQL-клиент (`rabisClient`) — нигде не используется.

### 2. Нарушение границ слоёв (обратная зависимость)
**Файл:** `src/mcp/dataLayer/resources.ts → src/app/services/graphql.service.ts`  
MCP модуль импортирует сервис из `app/`. Нужно инвертировать: MCP зависит от собственного слоя данных.

### 3. Сессии живут только в памяти (`Map`)
**Файл:** `src/mcp/services/history.service.ts:5`  
При рестарте MCP-сервера все сессии и чаты пропадают.

## 🟡 Средние

### 4. `classifyShortMessage` существует, но никогда не вызывается
**Файл:** `chat.controller.ts:69` — `activatedLayers = ['DATA']` (хардкод). Классификатор слоёв бесполезен.

### 5. Нет обработки разрыва MCP-соединения
**Файл:** `chat.controller.ts:40`  
После `connectWithRetry` соединение считается вечным. Перезапуск MCP сервера = crash на следующем запросе.

### 6. Негибкий порог «большого ТЗ» (маджик-число 1000)
**Файл:** `chat.controller.ts:119`, `history-promt.ts:43`  
Одно и то же число в двух местах. 1000 символов — слишком мало для "большого ТЗ".

### 7. Системный промпт проходит через user-роль → хрупкий детект по ключевым словам
**Файл:** `ai.service.ts:72-81`  
`textContent.includes('ИНСТРУКЦИЯ')` — любое изменение промпта сломает логику.

### 8. `archiveExecutedActions` грубо обрывает контекст
**Файл:** `history.service.ts:67` — `.slice(0, -2)`  
Безумно обрезает последние 2 сообщения без сохранения сути рассуждений.

### 9. Инструменты — только CREATE, нет READ/QUERY
Сейчас ЛМ может создавать, но не может проверить существующие модули перед созданием. Ресурс `lowcode://schema/state` возвращает мок.

## 🟢 Низкий приоритет / улучшения

### 10. Дублирование `dotenv.config`
**Файл:** `app.ts:6`, `rabisClient.service.ts:3`  
Достаточно одного вызова на уровне entry point.

### 11. Tool calling идёт последовательно, не параллельно
**Файл:** `ai.service.ts:182`  
Модель могла решить создать 2 поля одновременно — они всё равно пойдут одно за другим.

### 12. Нет rate limiting / throttling
Параллельные запросы для одной сессии создадут гонку данных в chatHistory.

### 13. `Task` interface не совпадает с output планировщика
**Файл:** `types/session.ts` vs `ai.service.ts:34`  
Интерфейс имеет `{ layer, task, description }`,规划器返回 `{ id, description }`. Поля `.layer` и `.task` никогда не заполняются.
